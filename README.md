# Aurora

Настольный лаунчер Minecraft Java Edition для Windows и Linux x64. Автор проекта — **Fish Fox Lino** ([ffxlino](https://github.com/ffxlino)). Код — MIT.

Проект до версии 1.0. Рабочая ветка и локальные review-сборки могут быть новее [опубликованных выпусков](https://github.com/ffxlino/Aurora/releases). Поддержка платформ и проверки указываются для конкретного выпуска; Windows-проверка не подтверждает работу на Arch.

## Пользователю

1. Скачай готовый файл своей платформы из Releases. Node.js нужен разработчику, не пользователю готового лаунчера.
2. Войди через страницу Microsoft с кодом Aurora. Нужна Minecraft Java Edition; Client ID уже настроен. Пароль вводится только на странице Microsoft.
3. Создай сборку, импортируй .mrpack или установи готовую из каталога. Java для игры подготавливается автоматически.
4. Нажми «Играть». Для общей сборки сначала проверяется опубликованное обновление.

В приложении есть **«Справка» / F1** с поиском, инструкциями RU/EN и FAQ без интернета. Сайт и справка собираются из [content/help.json](content/help.json).

## Возможности и границы

- Modrinth и CurseForge: совместимые версии, обязательные зависимости, фильтры и источник ресурса. Ограничения распространения автора сохраняются; серверный ключ CurseForge не включается в EXE.
- Изолированные сборки, локальные файлы, категории клиент/сервер/оба, предупреждения о дубликатах, обновления с просмотром версий, удаление и отключение модов.
- Резервные копии, диагностика и очищаемые отчёты; отдельные память, Java, параметры запуска, настройки игры и консоль.
- Общие сборки: постоянный сервер прав и журнала, приглашения редакторов и публичная библиотека Aurora-Packs. Публикуются **только mods и config**, не миры. Проверь права на вложенные моды и секреты в конфигурациях.
- Экспорт .mrpack и ZIP для сервера. Клиентские моды исключаются из серверного экспорта; неизвестные требуют ручной проверки.
- Список серверов и основной сервер в боковой панели. Ping даёт игроков и доступность; CPU/RAM/TPS зависят от API панели. SFTP/FTPS/FTP сравнивают и скачивают файлы, не меняя работающий сервер.
- Передачи показывают скорость и примерное время. SFTP-сравнение отменяется; повторные проверки могут использовать кеш до 10 минут. Полная проверка и включённая проверка перед запуском читают содержимое заново.
- Системное хранение токенов, RU/EN, темы и настройка цветовой палитры. JAR выполняет сторонний код; известный источник и хеш не гарантируют безопасность мода.

Единый архив общей публикации должен быть меньше 2 ГиБ; суммарный лимит файлов сборки — 4 000 000 000 байт. Бесплатные квоты провайдеров могут временно остановить операции. GitHub-хранилище сборок не является игровым сервером.

## Разработка

Требуются Node.js и npm:

```text
npm ci
npm run runtime:install
npm run content:build
npm test
npm start
```

Windows: `npm run dist -- --publish never`. Linux: `npm run dist:linux -- --publish never` на Linux. Контент и лицензии подготавливаются перед упаковкой. Локальный сайт: `node scripts/preview-site.cjs` — адрес выводится при старте.

Облако: `npm ci --prefix cloud`, `npm test --prefix cloud`. Не размещай токены в исходниках, .env примерах, логах или клиенте. Изменение секретов и публикация сервера — отдельные действия.

Стандартный канал исключает draft/prerelease. Начиная с локальной 0.14 нужен Aurora-update.json с Ed25519-подписью, привязанной к точному файлу, SHA-256, размеру, версии и сроку действия; есть локальная защита от отката и ротация дочернего ключа. Первую 0.14 нужно получить доверенным способом. Это не Windows Authenticode: предупреждение Windows возможно. [Порядок выпуска и ключей](documentation/RELEASING_RU.md).
