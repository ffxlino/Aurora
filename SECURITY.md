# Безопасность Aurora

## Поддерживаемые версии

Проект находится до версии 1.0. Исправления предназначены для актуального выпуска; отдельной ветки LTS нет. Локальные review-сборки не являются автоматически опубликованными стабильными обновлениями. Пользуйся версиями из https://github.com/ffxlino/Aurora/releases .

## Сообщение об уязвимости

Приватные отчёты GitHub включены и проверены через API 15 октября 2026. Войди в GitHub и отправь отчёт: https://github.com/ffxlino/Aurora/security/advisories/new . Этот канал не предназначен для обычных багов.

Если приватная форма недоступна, создай запрос на приватный контакт без технических деталей эксплуатации, токенов и пользовательских данных. Не публикуй уязвимость с рабочими секретами в обычном Issue. Корпоративный email не обязателен для этой формы. Контакт для запросов о персональных данных и регламент ответа ещё нужно определить; круглосуточного SLA сейчас нет.

Укажи версию, платформу, минимальные шаги, ожидаемое и фактическое поведение, возможное влияние и безопасное доказательство. Проверяй только свои локальные экземпляры и специально разрешённую тестовую среду. Не тестируй нагрузку, доступ к чужим данным или атаки на общедоступный Worker без отдельного разрешения.

## Границы защиты

- Контекст интерфейса изолирован, Node.js в нём не предоставляется; IPC допускает фиксированный список действий.
- Токены и пароли используют системное защищённое хранилище; JAR, миры и произвольные конфиги не шифруются автоматически.
- API-ключи серверных интеграций не должны попадать в EXE, сайт, логи и Git.
- Начиная с локальной 0.14 обновление требует Ed25519-подпись Aurora-update.json с ключом, закреплённым в приложении. Проверяются версия, платформа, размер, SHA-256, срок действия, последовательность и делегирование нового ключа. Закрытый ключ хранится отдельно от GitHub в системном хранилище автора.
- Первая установка 0.14 требует доверенного получения самого EXE: старый клиент ещё не знает новый ключ. Файл не имеет Windows Authenticode-подписи; Ed25519 не убирает предупреждения Windows.
- Защита от отката использует локальный журнал доверия. Удаление профиля удаляет этот журнал; подмена локального приложения или компрометация корневого ключа вне этой гарантии. Контрольные суммы и подписи не доказывают безопасность сторонних модов.
- SFTP привязан к отпечатку ключа. Не обходи эту проверку при смене ключа — сверь его с администратором.

План усиления и открытые вопросы: documentation/PROJECT_AUDIT_RU.md . Это описание реализованных механизмов и ограничений, а не сертификат безопасности.
