# Сайт Aurora: подготовка, проверка и публикация

Сайт находится в `docs/`, без обязательной серверной части, регистрации и внешних шрифтов. Есть 12 страниц: главная, загрузки, руководство, FAQ, поддержка, дорожная карта, история, безопасность, лицензии, конфиденциальность, условия и 404.

Контент справки: `content/help.json`. Правовые исходники: `legal/`, `SECURITY.md` и `LICENSE`. Генерация: `npm run content:build`. Результат справки автоматически включается в лаунчер. Не правь сгенерированные HTML и help-content.js вместо исходников.

Локально можно открыть `docs/index.html` обычным браузером. Для полной проверки в условиях HTTP запусти `node scripts/preview-site.cjs`; адрес выводится в консоль. Файлы для передачи владельцу — архив Aurora-Website-0.14-review.zip. Наличие архива не означает размещение сайта в интернете.

## Что проверено

- Основная страница и переходы, поиск FAQ и руководства.
- Мобильный экран 390×844: меню раскрывается, горизонтального переполнения нет.
- Страница загрузок читает реальные stable-выпуски GitHub. Не предлагает draft/prerelease и проверяет точное совпадение адреса файла с репозиторием.
- Если API GitHub недоступен, остаётся рабочая ссылка на Releases. Отсутствующий Linux-файл не подменяется Windows-файлом или выдуманной ссылкой.
- Проверяются внутренние ссылки и якоря всех HTML, заголовки и наличие локальных ресурсов.
- Нет рекламной аналитики, форм отправки паролей, сторонних шрифтов и собственного приёма платежей.

## Перед публикацией

1. Владелец просматривает сайт, FAQ и документы. Подтвердить оператора, страну и контакт для запросов о данных по LEGAL_RELEASE_CHECKLIST.md; публичное имя Fish Fox Lino уже подтверждено.
2. Не менять действующую MIT на запретительную лицензию задним числом. Не обещать регистрацию Aurora или подпись EXE, пока их нет.
3. Проверить актуальную доступность выпусков и описание тестов Windows/Linux. Локальная 0.14 не должна появиться в стабильном канале без отдельного выпуска.
4. Скопировать проверенные исходники и `docs/` в публикационный checkout, проверить diff и отсутствие .env, токенов, аккаунтов, журналов и пользовательских сборок. В этой задаче такое копирование и push не выполняются.
5. После отдельного разрешения владельца использовать существующий GitHub Pages workflow для каталога `docs/`. Новый платный сервис и карта не требуются. Альтернатива — статическое размещение в уже настроенном Cloudflare Pages; не путать его с Worker прав и каталога.
6. После размещения проверить настоящий адрес главной, загрузки, FAQ, 404 и политик; затем убрать пометку предварительной редакции и обновить канонический адрес, если выбран иной домен.

GitHub Private Vulnerability Reporting включён и проверен через API. Ссылка на приватный отчёт работает после входа в GitHub; отдельного корпоративного почтового ящика не создано.
