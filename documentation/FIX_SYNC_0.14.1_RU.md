# Aurora 0.14.1: восстановление файлов общей сборки

## Причина

Синхронизация завершалась сразу при совпадении номера общей версии либо contentId. Эти значения описывают опубликованную версию, но не доказывают наличие и целостность локальных файлов. Ручное удаление mods/config оставляло прежние метаданные, поэтому запуск пропускал скачивание.

## Изменение

Перед каждым запуском общей сборки проверяются фактические SHA-256 всех файлов опубликованного манифеста. Отсутствующие файлы скачиваются даже при совпадающей версии. Локально изменённые файлы требуют подтверждения замены; перед применением создаётся резервная копия. Ошибка получения манифеста, скачивания или проверки целостности прерывает запуск.

В окне «Синхронизация» появилась кнопка «Восстановить с сервера». Она получает текущую опубликованную версию, доступна и читателю, не публикует локальное удаление в общую сборку. Дополнительные личные файлы, отсутствующие в общем манифесте и предыдущем списке управляемых файлов, сохраняются. Миры не затрагиваются.

Если все файлы совпадают, повторное скачивание и новая резервная копия не создаются. При изменении только метаданных актуализируется связь с общей версией после проверки содержимого. В статусе отображается прогресс проверки файлов.

## Проверки

- Восстановление отсутствующих JAR и конфига из проверенного единого mrpack при прежней версии/contentId.
- Сохранение миров и дополнительных личных модов; повторная проверка без скачивания и лишних копий.
- Обнаружение изменённого конфига при прежней версии, подтверждение замены и возврат личного файла из резервной копии.
- Отказ принять новую ревизию с тем же contentId, если загружаемый файл повреждён.
- Полный набор: 120 тестов прошли, один тест Linux пропущен. Проверка интерфейса в отдельном чистом профиле успешна.

Исправление относится к общей библиотеке Aurora, а не к загрузке файлов на работающий игровой сервер по SFTP. Публичная версия и сервер не изменялись.
